Домашнее задание 3. Проведение юнит-тестов с помощью PyTest
Информация о выполнении задания
Задание выполняется на оценку индивидуально.

Содержание задания
Цель задания
Применить инструменты PyTest (фикстуры, параметризацию, мок-объекты при необходимости) и написать тесты, учитывая как позитивные, так и негативные сценарии.

Условия
Вам необходимо написать минимум 2 позитивных и 2 негативных теста для каждой функции (всего 5 функций), используя PyTest (можно использовать фикстуры и параметризацию). При необходимости примените mock-объекты, например, для внешних вызовов БД, отправки почты.

Выберете сервис, для которого будете проводить тестирование (Booking-сервис или Task Manager).
Создайте проект (или несколько файлов) для тестов.
Напишите PyTest-тесты для 5 указанных функций (2 позитивных и 2 негативных на каждую).
Оформите так, чтобы можно было запустить тесты командой pytest и увидеть результат.
(Опционально) Добавьте README или комментарии, как запускать тесты и что именно вы проверяете в каждом.
Алгоритм проведения юнит-теста
Booking-сервис
calc_price(base_price: float, discount: float, count: int) -> float:

Рассчитывает итоговую сумму за count билетов с учетом базовой цены и возможной скидки.
Учесть граничные случаи (количество билетов = 0, отрицательная скидка, большие числа).
check_availability(event_id: int, seats_requested: int) -> bool:

Проверяет наличие свободных мест.
При нехватке мест возвращает False, иначе — True.
Можно замокать вызов БД или внешнего метода, чтобы возвращать текущее количество оставшихся билетов.
apply_promo_code(order_id: int, promo_code: str) -> bool:

Применяет промокод к заказу, если он действителен.
Проверка на истекший/невалидный промокод, исчерпанный лимит использования.
Тесты могут включать моки или заглушки для обращения к репозиторию промокодов.
generate_booking_ref(user_id: int, event_id: int) -> str:

Генерирует уникальный код/референс бронирования на основе идентификаторов пользователя и события.
Можно проверить формат (например, BOOK-<user_id>-<event_id>-<random_suffix>).
Учесть уникальность результата при повторных вызовах.
send_notification_email(email: str, booking_details: dict) -> bool:

Отправляет уведомление на почту при успешном бронировании/оплате.
Можно использовать мок-объект отправки почты (SMTP или любой mail-сервис).
Проверить, что функция возвращает True при успехе и обрабатывает исключения (например, недоступность почтового сервера).
Task Manager
create_task(project_id: int, title: str, deadline: datetime) -> int:

Создает задачу в рамках проекта, возвращает Task id.
Проверить валидные и невалидные данные (пустой заголовок, прошедшая дата дедлайна, несуществующий project_id).
track_time(task_id: int, hours: float) -> float:

Добавляет отработанные часы к задаче с task_id.
Проверить корректность при разных входных значениях (0 часов, отрицательное число, очень большие числа).
Можно мокать доступ к базе данных для обновления задачи.
calculate_invoice(hours: float, rate: float, currency: str) -> float:

Рассчитывает сумму счета на основе потраченных часов и почасовой ставки с учетом валюты.
Тестировать граничные случаи (0 часов, нулевая ставка, непредусмотренная валюта).
Проверить корректность округления результата, если это требуется.
check_project_deadline(project_id: int) -> bool:

Возвращает True, если проект еще не просрочен, и False, если дедлайн пройден.
Нужно определить, как функция получает данные о проекте (мокать базу или репозиторий).
Проверить, что функция корректно обрабатывает случай, когда дедлайн сегодня/завтра/был вчера.
send_task_notification(email: str, task_info: dict) -> bool:

Отправляет уведомление пользователю о состоянии задачи (создана, завершена, просрочена).
Как и в первом варианте, можно мокать сервис отправки писем.
Проверить обработку ошибок (невалидный email, сбой SMTP).
