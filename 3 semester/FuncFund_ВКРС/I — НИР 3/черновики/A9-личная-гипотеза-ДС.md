## Роль в проекте

Соло-основатель: продуктовая аналитика, пайплайны данных портфеля, оценка качества агрегации и импорта, эксперименты по согласованности valuation.

## Проблема в зоне ДС

При агрегации из разных источников (брокерский отчёт, ручной ввод, биржевые котировки) пользователь получает «единую картину» только если пайплайн корректно сопоставляет инструменты, оценивает позиции и сохраняет историю. Ошибка классификации/оценки разрушает УЦП «вместо Excel».

## Теоретический задел (кратко → развернуть в отчёте)

- CustDev n=14: автоагрегация — топ-критерий (9.1/10); боль ручной сверки.
- Конкуренты (Snowball, Intelinvest, кабинеты брокеров): сильные внутри экосистемы; кросс-брокерный импорт — узкое место.
- Практика data pipelines: normalize → enrich (dictionary/MOEX meta) → value (котировки) → snapshot (ClickHouse) → serve (history/WS).
- Метрики качества данных: parse success rate, coverage классов активов, relative error valuation vs эталон (ручная сверка / исходный отчёт).

## Гипотеза (опровержимая, с метрикой)

> **H_DS:** Пайплайн FuncFund «импорт Сбер HTML → нормализация тикеров через dictionary/MOEX → live valuation + снапшоты ClickHouse» на выборке бета-портфелей DIY-инвесторов MOEX обеспечивает:
>
> 1. **parse success rate ≥ 80%** файлов Сбер без ручной правки парсера;
> 2. **согласованность оценки:** для ≥80% успешно импортированных портфелей относительное расхождение суммарной стоимости позиций между (a) суммой в исходном отчёте / ручной сверкой пользователя и (b) valuation MVP **≤ 5%** (исключая заведомо неликвидные/некотируемые позиции, которые помечены отдельно);
> 3. при добавлении **второго источника** (ручной ввод или 2-й брокер) доля пользователей, у которых на одном экране видны **≥2 источника**, растёт до **100%** тестовой группы (n≥5), и медианное время сборки портфеля **&lt; 15 мин**.

Нулевая гипотеза для пункта 2: расхождение &gt;5% у большинства портфелей → гипотеза опровергнута, нужен пивот парсера/словаря/правил valuation.

## Методика (7 шагов)

1. Зафиксировать baseline: текущий парсер Сбер + dictionary v3 + fetcher MOEX/CBR/Binance + ClickHouse snapshots (код в `funcid/funcfund`).
2. Собрать выборку: ≥5 бета-пользователей с реальными (или анонимизированными) отчётами Сбер; протокол с эталонной суммой портфеля.
3. Прогнать импорт; зафиксировать success/fail и класс ошибки (parse / map ticker / quote missing).
4. Для успешных: сравнить Σ valuation MVP vs эталон; посчитать относительную ошибку \(e = |V_{mvp}-V_{ref}| / V_{ref}\).
5. Повторить сценарий «+ второй источник» (manual / Т-Инвестиции); замерить время и число источников на дашборде.
6. Свести таблицу экспериментов (подход × метрика × n); при fail — правка парсера/словаря, повтор.
7. Интерпретация: подтверждена / частично / опровергнута; бэклог на НИР 4 (второй парсер, TWR, мониторинг качества).

## Метрики качества (ДС)

| Метрика | Формула / определение | Цель НИР 3 |
|---|---|---|
| Parse success rate | успешные импорты / попытки | ≥80% |
| Valuation relative error | \|V_mvp − V_ref\| / V_ref | ≤5% у ≥80% кейсов |
| Quote coverage | позиции с котировкой / все торгуемые | ≥95% MOEX liquid |
| Time-to-value | мин до дашборда с данными | медиана ≤15 |
| Multi-source rate | пользователи с ≥2 источниками / бета | →100% тестовой группы |

## Baseline (черновик B8)

- **Без ML:** rule-based HTML parse (Сбер) + dictionary lookup + market prices.
- Альтернативы к сравнению (окт–нояб): (A) только manual; (B) Сбер+manual; (C) +второй брокер — когда парсер готов.
- «Качество» = parse success + valuation error, не ML accuracy.
