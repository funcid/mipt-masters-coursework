# A10. План эксперимента для MVP (версия 1)

**Дата:** 20.10.2026 · Связь: A8 (продукт), A9 (ДС).

## Цель эксперимента

Проверить, получает ли ICP волны 1 **первую ценность** от MVP (единая картина портфеля) и готовы ли платить / продолжать при появлении 2-го источника.

## Кого тестируем

| Параметр | Значение |
|---|---|
| Сегмент | DIY MOEX, 2+ счёта, ручная сверка |
| Источник кандидатов | CustDev-респонденты (согласия на бету получены) |
| n минимум | **5** человек с протоколом |
| Исключения | нет реального брокерского отчёта; ждут сигналы buy/sell как must-have |

## Что измеряем

См. таблицы метрик в A8 и A9. Обязательный минимум в протоколе:

1. Удалось ли зарегистрироваться и пройти онбординг (да/нет, минуты).
2. Импорт Сбер: успех / ошибка (текст).
3. Оценка «закрывает боль сверки» 1–10.
4. Эталонная сумма портфеля vs сумма в MVP (если пользователь готов дать).
5. Готовность платить (да/нет/цена).
6. Топ-3 замечания → бэклог.

## Дизайн

1. **Сценарий A (сейчас):** регистрация → импорт Сбер → ручной добор недостающего → дашборд+WS → history (Premium demo при необходимости).
2. **Сценарий B (после B7):** то же + 2-й источник (Т-Инвестиции или второй файл/manual как «источник»).
3. Наблюдение модерируемое (30–40 мин) + короткий опросник.
4. Фиксация: протокол Markdown/PDF + скрин (по согласию) + issue в трекере.

## Критерии успеха / провала (решение)

| Решение | Условие |
|---|---|
| Идём в пилот 4 сем. | ≥60% ≥7/10 по боли **и** parse≥80% **и** нет блокера «не вижу портфель» |
| Доработка MVP, повтор бета | 40–60% или parse 50–80% |
| Пивот УЦП/сегмента | &lt;40% **или** массовый запрос «дайте сигналы» (ломает позиционирование) |

- Респонденты не присылают отчёт → дать anonymized sample + их manual.
