# A9. Личная гипотеза в зоне роли (Разработка IT-продукта)

**Проект:** FuncFund · **Студент:** Царюк Артём Владимирович  
**Программа:** Разработка IT-продукта · **Версия:** 3.0 · **Дата:** 12.11.2026  
Декомпозиция рабочей гипотезы продукта ([A8](A8-гипотеза-продукта-УТП-метрики.md)) под личную роль соло-основателя.

> Программа: **Разработка IT-продукт**. Техметрики parse/e — **контроль качества данных** в B8/B9, не главная гипотеза роли.

## Роль в проекте

Соло-основатель: product owner и единственный разработчик. Проблема и УЦП, CustDev, приоритизация MVP; архитектура и реализация пайплайна импорт → нормализация → оценка → снапшоты → live (6 сервисов), мобильный клиент, деплой на funcfund.ru; метрики пилота, GTM/юнит для волны 1.

## Проблема в зоне роли

DIY-инвесторы MOEX с 2+ счетами/источниками тратят заметное время на ручную сверку Excel и приложений и не получают единой картины портфеля. Без рабочего онбординга (импорт → дашборд) УЦП «вместо Excel» не проверяется.

## Теоретический / эмпирический задел

- CustDev n=14: автоагрегация — топ-критерий (9.1/10); боль ручной сверки.
- Конкуренты (кабинеты брокеров, Финуслуги, Snowball, ИИ): сильны в своём контуре; кросс-брокерный учёт без buy/sell — пробел.
- Продуктовая рамка: ICP → JTBD «свести счета» → MVP → бета → pay intent.
- Контроль качества данных (supporting): success импорта, TTV, согласованность суммы vs эталон (B8/B9).
- Выбор порогов: **TTV ≤ 15 мин** — нижняя граница текущей ручной сверки (15–20 мин по CustDev), продукт должен быть быстрее Excel; **≥ 7/10** — оценка боли в верхней трети шкалы.

## Гипотеза (опровержимая, с метрикой)

**Вмешательство одно:** автоимпорт счетов вместо ручного ввода позиций. **Baseline:** ручной ввод тех же 2 источников (17.6 мин на smoke P1).

> **H_prod (роль):** Если DIY-инвестор MOEX с 2+ счетами подключает их **через автоимпорт** (а не ручным вводом позиций), то на бете **n ≥ 5**:
>
> 1. медиана **TTV ≤ 15 мин** и импорт без поддержки **≥ 80%** попыток;
> 2. **≥ 60%** оценят закрытие боли сверки на **≥ 7/10**.

**Опровержение:** медиана TTV &gt; 15 мин, **или** импорт &lt; 80%, **или** &lt; 60% ставят ≥ 7/10.

Готовность платить (≥ 40% pay intent при ≥ 2 990 ₽/год) вынесена в рабочую гипотезу проекта ([A8](A8-гипотеза-продукта-УТП-метрики.md)): она проверяется на той же бете, но не входит в личную гипотезу, чтобы не смешивать два исхода.

### Формулы метрик

- **TTV** = t(первый дашборд с данными) − t(регистрация), мин; по участнику берётся медиана.
- **success импорта** = успешные импорты без обращения в поддержку / все попытки импорта.
- **e** (контроль качества) = |V_FuncFund − V_брокер| / V_брокер, на успешных импортах.
- **Закрытие боли** = доля участников с оценкой ≥ 7 по шкале 1–10 на вопрос «насколько FuncFund закрывает сверку ваших счетов».

## Методика (7 шагов)

1. Зафиксировать ICP, сценарий «сверка 2+ счетов» и пороги (этот документ).  
2. Подготовить MVP: автоимпорт Сбер (HTML) / ВТБ (отчёт) / Т (API) + ручной ввод как baseline, деплой, legal/checkout.  
3. **Выборка:** ≥ 5 бета-участников из базы CustDev (DIY MOEX, 2+ счёта), набор через Telegram; согласие на участие.  
4. **Контроль переменных:** в каждом прогоне ровно 2 источника; меняется только способ ввода (ручной → автоимпорт).  
5. Протокол: регистрация → импорт → дашборд; замер TTV и success по логам.  
6. Опрос сразу после сценария: закрытие боли 1–10 (+ pay intent для гипотезы проекта).  
7. Контроль качества: e на успешных импортах (B9) → интерпретация: подтверждена / частично / опровергнута → бэклог.

**Ограничения:** smoke P1 — n = 1, собственный портфель автора; на бете — малая выборка, вывод без статистической значимости.  
**Этика и данные:** согласие участника; токен Т-API только read-only; персональные данные — по 152-ФЗ.

## Метрики роли (НИР 3)

| Метрика | Цель | Провал |
|---|---|---|
| TTV (медиана) | ≤ 15 мин | &gt; 15 мин |
| Success импорта | ≥ 80% | &lt; 80% |
| Оценка закрытия боли | ≥ 60% беты ставят ≥ 7/10 | &lt; 60% |
| e (контроль качества) | ≈ 0 | расхождение суммы с брокером |

## Что уже есть (11.11.2026)

- MVP live: Сбер + Т + ВТБ + manual, ЮKassa, OAuth, funcfund.ru  
- Smoke P1 (B9): всегда **2 источника**; ручной 17.6 мин → автоимпорт 4.5 мин (в 3.9 раза) → авто (макс.) 0.9 мин; e ≈ 0.001%  
- CustDev-база кандидатов в бету  

**Статус H_prod:** частично подтверждена — TTV ✓ на n = 1; success импорта и закрытие боли проверяются на бете n ≥ 5 до 05.12.
