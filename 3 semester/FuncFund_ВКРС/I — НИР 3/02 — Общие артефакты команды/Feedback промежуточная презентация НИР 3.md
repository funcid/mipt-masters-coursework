- Соло-стартап → в задачах нужно **охватить все продуктовые части**: работа с пользователем, обратная связь, исследования.

- Нужны **нетривиальные** исследования в архитектуре / том новом, что даёт преимущество относительно других проектов.
- **Личная гипотеза не декомпозирована** из рабочей: не видно цепочки «рабочая → ряд исследований».

### Эксперт (Александр) — «это ситуация, а не проблема»

- Формулировка «всё в одном месте / разные счета» — **ситуация**, а не проблема: «проблемы здесь нет, я не вижу».
- Связка «неполная картина → неоптимальные решения → теряете деньги» **не прозвучала убедительно** в выступлении («кто вам это сказал?… в вашем выступлении я не услышал»). Нужна более глубокая постановка проблемы с доказательствами.
- Жёстко проверяли ICP «2+ счёта на Мосбирже»: сколько таких людей, откуда цифра, из этой ли выборки CustDev.

### Эксперт (после Кирилла) — «красивый Excel», зачем приложение

- Уточнил продуктовый скоуп: **агрегатор/дашборд без операций buy/sell** из интерфейса — это понятно.
- Ключевой вопрос ценности: **зачем веб/мобильное приложение**, если интеграции через API очевидны и это можно собрать скриптом / плагином / «улыбкой»?
- По «вкусу» эксперта в УЦП **не хватает следующего действия** после сводки: «окей, все активы на одной странице — а что с ними делать? Как выбрать решение?» Сейчас это выглядит как «очень красивая репрезентативная Excel».
- Без ответа «как применять инсайт» (особенно при волатильности) ценность представления данных слабая.

> Замечание про **безопасность загрузки данных** в устной части почти не раскрыто — оно есть в письменной сводке комиссии; к пересдаче закрывать отдельно.
