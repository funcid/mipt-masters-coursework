## 1. Краткое описание

Веб-приложение — витрина интернет-магазина промышленного и бытового освещения завода лампочек. В каталоге **ровно 20 наименований** (фиксированный набор на запуск; расширение — через админку). Пользователь добавляет товары в корзину, оформляет заказ. Администратор через панель управления ведёт каталог (CRUD), просматривает заказы и меняет их статусы.

## 2. Цели и границы (scope)

**Входит в объём ДЗ2–4 (реализация по этому ТЗ):**

- Публичная витрина: список товаров, карточка товара, корзина, оформление заказа, страница «Спасибо за заказ».
- Админ-панель: вход, список/редактирование товаров, список заказов, смена статуса заказа, журнал действий (чтение).
- Три микросервиса с **отдельными** схемами БД и HTTP API (см. разд. 5–7 и папку `microservices/`).
- Контейнеризация сервисов и `docker-compose` для локального запуска (заложено на последующие работы; в ТЗ — требование к результату).

**Сознательно упрощено (можно расширить позже):**

- Оплата: только фиксация «ожидает оплаты / оплачен вручную» без интеграции с платёжным провайдером.
- Клиент не регистрируется: при оформлении заказа вводит ФИО, телефон, email, адрес доставки.
- Одна валюта (RUB), НДС в цену можно не выделять.

## 3. Роли

| Роль | Действия |
|------|-----------|
| Гость | Просмотр каталога и карточек, формирование корзины (сессия/корзина на сервере). |
| Покупатель (без ЛК) | Оформление заказа из корзины. |
| Администратор | Вход в админку, CRUD товаров, просмотр заказов, смена статуса, просмотр аудита. |

## 4. Прототипы (Figma или аналог)

Необходимые экраны (достаточно low-fi / mid-fi):

1. **Главная** — баннер завода, блок «Хиты», ссылка в каталог.
2. **Каталог** — сетка карточек (фото, название, цена, кнопка «В корзину»), фильтр по типу цоколя (E14/E27/GU10 и т.д.) — опционально.
3. **Карточка товара** — галерея, характеристики (мощность, цоколь, цветовая температура, срок службы), цена, количество, «В корзину».
4. **Корзина** — список позиций, изменение количества, удаление, итог, кнопка «Оформить».
5. **Оформление заказа** — форма контактов и адреса, комментарий, подтверждение.
6. **Успешное оформление** — номер заказа, краткая сводка.
7. **Админ: вход** — email/пароль.
8. **Админ: товары** — таблица 20 позиций, поиск по SKU/названию, кнопки создать/редактировать/деактивировать.
9. **Админ: форма товара** — все поля из модели каталога.
10. **Админ: заказы** — таблица, фильтр по статусу, переход в карточку заказа.
11. **Админ: карточка заказа** — состав, контакты, смена статуса.
12. **Админ: аудит** — последние N записей (кто/что/когда).

Ссылка на макет: см. блок «Прототип (Figma)» в шапке документа и файл `ссылки-для-облачной-папки.txt` (дублирование для облачной папки сдачи).

## 5. Микросервисы и ответственность

| Сервис | Назначение | Собственная БД |
|--------|------------|----------------|
| **catalog-service** | Категории, товары, цены, признак активности, складские поля (упрощённо). | `catalog_db` |
| **order-service** | Корзина (по `session_id` или `cart_token`), позиции, заказы, статусы. | `order_db` |
| **admin-service** | Учётные записи админов, выпуск access/refresh JWT (или session), аудит действий; настройки витрины (контакты завода в подвале). | `admin_db` |

**Клиентская логика:** публичный SPA обращается к `catalog-service` и `order-service`. SPA админки после логина хранит токен, для товаров/заказов — к `catalog-service` / `order-service` с заголовком авторизации (см. интеграцию ниже). Запись в аудит — вызов `admin-service` (fire-and-forget или из BFF на фронте не делаем; на этапе реализации ДЗ3–4 допускается вызов аудита из бэкенда каталога webhook’ом; в ТЗ зафиксируем: **админский UI после успешного изменения в каталоге/заказе вызывает `POST /api/v1/audit-events` в admin-service**).

## 6. Интеграция и безопасность (для реализации)

- Публичные GET каталога — без токена.
- Изменение каталога и смена статуса заказа — только с **Bearer JWT**, выданным `admin-service` (роль `ADMIN`). `catalog-service` и `order-service` проверяют JWT по общему публичному ключу / секрету (деталь реализации — на усмотрение исполнителя; в ТЗ зафиксировано: обязательная проверка подписи и роли).
- Корзина гостя: при первом визите фронт получает `cart_token` (UUID) от `order-service`, хранит в `localStorage`, передаёт в заголовке `X-Cart-Token`.

## 9. Статусы заказа

`NEW` → `CONFIRMED` → `ASSEMBLING` → `SHIPPED` → `DELIVERED`; ветка отмены: `CANCELLED` (из `NEW` или `CONFIRMED`).

## 10. Нефункциональные требования

- REST, JSON UTF-8.
- Идентификаторы — UUID (строка) в API.
- Ошибки: единый формат `{ "error": { "code": "...", "message": "..." } }`.
- Время в ISO-8601 UTC.
