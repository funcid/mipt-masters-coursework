# Booking API Tests

## Цель задания

Научиться создавать коллекции Postman с запросами к API, автотестами и переменными окружения.

---

## Выбранный сервис

**Booking-сервис** — управление мероприятиями, бронированиями и оплатой.

---

## Состав коллекции

Коллекция **Booking API Tests** включает 5 запросов:

1. **Login User** `[POST] /api/auth/login`

   * **Цель:** авторизация пользователя.
   * **Тесты:**

     * Код ответа = 200
     * Ответ содержит поле `sessionId`
   * **Переменные:**

     * `auth_token` — сохраняется `sessionId` для последующих запросов

2. **Get Events** `[GET] /api/events`

   * **Цель:** получить список мероприятий с возможной фильтрацией по `sportType`, `date`, `location`.
   * **Тесты:**

     * Код ответа = 200
     * Ответ — массив объектов
     * Каждый объект содержит поля `id`, `title`, `date`

3. **Create Booking** `[POST] /api/bookings`

   * **Цель:** создание новой брони для выбранного мероприятия.
   * **Тесты:**

     * Код ответа = 201
     * Ответ содержит `bookingId`
   * **Переменные:**

     * `bookingId` — сохраняется для оплаты и получения деталей

4. **Pay Booking** `[POST] /api/payments`

   * **Цель:** оплата ранее созданной брони.
   * **Тесты:**

     * Код ответа = 200
     * Статус оплаты = `PAID`

5. **Get Booking Details** `[GET] /api/bookings/{bookingId}`

   * **Цель:** получить информацию о конкретной брони.
   * **Тесты:**

     * Код ответа = 200
     * Объект брони содержит `bookingId`, `status`, `eventTitle`

---

## Переменные окружения Postman

| Переменная   | Описание                | Использование                               |
| ------------ | ----------------------- | ------------------------------------------- |
| `base_url`   | Базовый URL API         | Подставляется в запросы вместо хоста        |
| `auth_token` | Session ID после логина | Используется в заголовке Authorization      |
| `bookingId`  | ID созданной брони      | Используется для оплаты и получения деталей |

---

## Структура тестов

В Postman тесты написаны на JavaScript с использованием pm API:

```javascript
// Проверка кода ответа
pm.test("Status code is 200", () => pm.response.to.have.status(200));

// Проверка наличия поля
pm.test("Response has sessionId", () => pm.response.json().hasOwnProperty('sessionId'));

// Сохранение переменной окружения
pm.environment.set("auth_token", pm.response.json().sessionId);
```

* Все тесты выполняются автоматически при запуске запроса.
* Переменные окружения позволяют использовать динамические данные между запросами.

---

## Использование коллекции

1. Импортировать JSON коллекции в Postman (*File → Import → JSON*).
2. Убедиться, что переменные окружения (`base_url`, `auth_token`, `bookingId`) настроены.
3. Сначала выполнить **Login User**, затем остальные запросы.
4. При успешном прохождении всех тестов коллекция проверяет корректность работы API: авторизация, создание брони, оплата и получение данных.
